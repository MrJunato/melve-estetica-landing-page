# Fluxo de trabalho

## Etapas e aprovações
1. **Briefing** (`/briefing`): consolidar Instagram + respostas do formulário em `docs/BRIEFING.md`.
   - Separar: fatos confirmados / sugestões / pendências.
2. **Escopo e preço** (`/precificar`): preencher `docs/ESCOPO_E_ORCAMENTO.md`.
   - Exigir aprovação explícita antes de criar ou codar.
3. **Estratégia** (pós-aprovação): `conversion` define objetivo, público, sequência de seções e copy base.
4. **Direção visual** (pós-aprovação): `design` define paleta, tipografia, composição e imagens.
5. **Implementação**: `build` executa o aprovado; valida links, responsivo básico e build local quando a stack permitir.
6. **Revisão** (`/revisar-lp`): só o aspecto alterado; sem cascata.
7. **Publicação**: somente com autorização; registrar onde foi publicado e pendências.

## Checklist de entrega
- [ ] Escopo e orçamento aprovados
- [ ] Textos baseados em fatos confirmados
- [ ] Imagens autorizadas e otimizadas
- [ ] Mobile priorizado, hierarquia clara, um CTA principal
- [ ] Contato testado, links válidos
- [ ] Acessibilidade básica e SEO essencial
- [ ] Sem trackers/serviços não aprovados
- [ ] Verificações reais separadas de pendências

## Regras de contexto
- Consulte este fluxo e `AGENTS.md`; demais docs só quando a etapa exigir.
- Não releia mapas/guias nem busque docs remotos sem necessidade concreta.
- Registre apenas decisões duráveis; sem documentos extras por interação.
